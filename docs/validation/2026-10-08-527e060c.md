**Retail's race:** `/lua/ai/aiattackutilities.lua:952: Attempt to set attribute 'MovementLayer' on nil`, forked at `platoon.lua:2848` / `:2865`. It was traced to retail's scripts when it first showed in a Moho pathing game (seed 7777, with #435):
1. `EngineerReclaimDone`'s guard `not unit.PlatoonHandle.PlanName == 'EngineerBuildAI'` is always false, as Lua reads it: `(not x) == '…'`.
2. So `ProcessBuildCommand` runs for a ReclaimAI engineer, against a stale build queue.
3. A transport wait follows, ReclaimAI disbands the platoon, and the next site meets a nil platoon handle.

The scripts aren't patched.
- At ee8ab53b none of the four retail games met it. Here two do, one default and one Moho, because the games changed since (#438, #443).
- It is a timing race in the AI's engineer platoons, not tied to either pathing. Each run counts it as its one failed check.

**The FAF error** is `/lua/platoon.lua:1555: attempt to call method 'GetLocationCoords' (a nil value)`, forked at `adaptive-ai.lua:373`.
- It is the one the [2026-10-06 record](2026-10-06-e1f275b3.md) traced to FAF's scripts: `DisableAI` strips a defeated AI's bases of their managers, while its `ArmyPool` keeps running `BaseManagersDistressAI` over them.
