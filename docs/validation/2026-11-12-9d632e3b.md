## The simulation thread and the capture workers, on and off

The simulation normally runs on its own thread, and a worker pool captures the world for drawing (`docs/performance.md`). `--no-sim-thread` runs it serially, and `--no-workers` captures on the main thread. The sim thread's design asks for checksums to be compared with both on and off (`docs/plans/2026-10-16-sim-thread-design.md`). #791 compared the workers over 12,000 ticks of an eight-AI match.

**Method:**
- **Saves:** each game was played headless to tick 10 and saved (`--ai-skirmish --ai-armies <n> --ticks 10 --seed 4242 --save … --save-at 10`). A windowed game can't start AIs itself; a save fixes them, and the factions with them.
- **Runs:** each configuration then loaded the save and played it windowed, offscreen and unpaced (`--load … --fast-match <ticks>`). That is the session path the sim thread and the capture workers are in.
- **Recording:** `--checksum-trace` wrote every beat's checksum, domain by domain. `--match-telemetry` recorded the timings.
- **Order:** each run was booked on the gate by itself. The four configurations ran in one order for the four-AI game and in the reverse order for the eight-AI one.

**Result:** in both games the four configurations played the same game. Every beat matched in every domain of the trace, including the script threads that it only traces.

- **Wall time:** a fast match collects each sim job before its next fixed frame, so the sim thread changes its wall time little; within 4% here. The thread's gain is frame pacing in a paced game, which `--play-for` measures. The serial runs' worst ticks are a third longer in the four-AI game.

## The default pathing's reference games (#1011)

- **Coverage:** `test_cross_platform`'s pinned game has no map, so its units never take the default pathing. #1011 adds four games on Moho's pathing: a crowd through a gap; the same crowd made from spent ids; stunned tanks; and ships, hovercraft and amphibious tanks on a lake.
- **Pinned and saved:** each pins its checksum, and each is saved mid-motion and played on to the same value.
- **Results:** on this machine's Debug build all four pass, as do the 20 `[moho_pathing]` tests. On the PR's head (0f08592c), all six CI jobs passed: GCC, Clang (with the clang-tidy ratchet), ASan, MSVC, macOS on arm64 and `cross-os-play`. Each of the first five reached all four pinned values, so the default pathing plays these games alike on every platform CI builds.
- **The stun rule:** a stun longer than 30 beats ends a unit's move where it stands, as in the original game. Moho's path navigator counts a beat without movement as no progress unless the unit is `UNITSTATE_Immobile`, and a stun doesn't set that state (Steam exe 0x5B55BF). The engine already did this, and the stun game pins it.
